Architecture ​

Ports-and-adapters over a flat crates/ workspace. cuora-core is pure domain — cuora:// refs, the redacting Secret newtype, the env axis, actor attribution — with no I/O. Ports are traits (cuora-config, cuora-vault, cuora-deploy); impls live in separate crates; crates/cuora-cli (package cuora) is the composition root that wires impls to verbs.

Design rules:

  • No unsafe, no async — the binary stays dependency-light and synchronous; vault impls that speak HTTP use a blocking client (ureq), so no runtime embeds anywhere.
  • Secret never exposes plaintext — no Display/Debug of the value; .expose() is the only way out, called at edges only (child env injection, cuora env exports, get).
  • Stores hold ciphertext only — every vault impl encrypts client-side with age (ADR-0001); a remote vault is ciphertext over the wire and at rest, never a plaintext service.
  • Ports are conformance-tested — cuora-testkit runs the same contract suite against every vault impl (cuora-vault-age, cuora-vault-cf): upsert/rotate/list/env-isolation semantics can't drift per backend.
  • One ops shell — cuora-ops owns config load, env→vault routing, the env-pin rule, and audit emission; the CLI and the TUI are both thin front-ends over it and cannot diverge.

Front-ends ​

  • cuora (CLI) — clap verbs + --json/manifest/schema for machines; the agent interface.
  • cuora ui (TUI) — a read-only ratatui browser over the same ops; feature-gated (--no-default-features for a lean binary).
  • cuora serve — ndjson IPC over the Vault port with an exec-driven [serve.pdp] policy-decision hook (ADR-0003); peregrin's embedding point.

Boundary — secret materialization only ​

cuora owns refs, vaults, env injection, redaction, and the audit wire. Neighbors own theirs — see boundaries for the full map.
