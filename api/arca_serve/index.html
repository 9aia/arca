arca-serve — arca serve: the ndjson request/response surface orchestrators (peregrin) embed (P-005).

One JSON request per stdin line, one JSON response per stdout line; the audit wire stays on stderr, unchanged — three separate fds, so a reply never rides the event stream and an event never answers a request. A thin front over arca-ops like arca-tui — every vault access goes through Ops, so env-pin resolution, [envs] routing, and the audit events are the same ones the CLI emits.

Protocol arca-serve/1:

{"id": 1, "op": "get", "ref": "arca://billing/stripe",
 "env": "prod", "actor": "agent:peregrin", "attestation": "…"}

→ {"id": 1, "ok": true, "result": {…}} or {"id": 1, "ok": false, "error": {"code": "…", "message": "…"}}. id is echoed verbatim — any JSON value, absent → null.

Ops: get/put/rm/rotate/list/check (each consults the configured [serve.pdp] first — list decrypts record metadata and check probes vaults including scoped-token gets, so they are materializations too), manifest (this protocol’s self-description), and shutdown (clean exit). run/env/deploy/init/ui stay single-shot CLI verbs — serve covers the port peregrin needs in-process.

Hard bounds on the wire: a request line over MAX_LINE_BYTES (4 MiB) answers bad_request and the reader resyncs to the next line; actor (256 B), attestation (64 KiB), ref (1 KiB), value (64 KiB), and id (4 KiB serialized) are each capped. Blank or whitespace-only lines get no reply — keep-alive whitespace is legal and unanswered.

Policy: requests carry advisory actor claims — actor is the attribution string audit records, attestation an opaque blob passed to the PDP verbatim. arca verifies neither; signing is the PDP’s side (P-005 is the boundary contract, not the enforcement). A configured PDP that denies — or that can’t be reached under the default fail-closed posture — turns into a denied/pdp_unreachable error, a denied audit event, and no vault access. manifest and shutdown are protocol meta-ops: they skip guardrails and the PDP consult by design (gating session lifecycle is the embedder’s spawn decision, not a materialization).

Values cross this wire deliberately: get returns them, put/rotate take them — the parent owns the channel exactly like it owns arca get’s stdout.

Constants§

MAX_LINE_BYTES
The most one request line may be — 4 MiB. Legitimate requests are bytes-to-kilobytes; an unbounded read_line lets a broken or hostile embedder exhaust memory, so an oversized line is a bad_request and the reader resyncs to the next line.

Functions§

run
Serve the ndjson loop on reader/writer against the loaded Ops — the arca serve verb’s whole job. Runs until EOF or a shutdown request. A malformed, non-UTF-8, or oversized line is a bad_request response, never a crash and never the end of the loop; only a real stdout/reader I/O failure propagates.
