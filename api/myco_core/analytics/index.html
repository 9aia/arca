Module analytics 

Source
Expand description

Analytics emits — roadmap/timeline, stats, and burnup over the filtered view universe (P-012). Pure domain: callers hand in filter-applied Scoped items (the same universe eval consumes); [myco-cli] renders the results. The design principle holds — fields are data, scheduling is config, views are emits: these functions only read Item fields and [[cycles]] config, never ledger state.

  • timeline — epic → milestone → cycle lanes, items placed by due:. An item lands in exactly one lane: its most specific scheduling field wins (cycle > milestone > epic); items with none land in ungrouped.
  • stats — count-by-dimension tallies (status, priority, owner, epic, milestone, cycle, label).
  • burnup — cumulative done:-stamped completions vs total scope per cycle (or one series when nothing is cycled). Items archived before the stamp existed count toward scope but never the curve — their completion date is unknowable.

Functions§

burnup
Burnup over [start, end] inclusive — one series per observed cycle: value plus one per declared-but-empty cycle, and a None series for uncycled items (last). Scope counts every item in the partition; done counts done:-stamped items whose stamp falls on or before each day — unstamped archive predates the field and never moves the curve.
burnup_window
The burnup window — the [[cycles]] window covering today when one exists (the in-flight iteration), else the trailing 8 weeks. Rollover is manual: outside every declared window the emit falls back rather than guessing.
stats
Count-by-dimension tallies over the filtered universe. Children count too when the caller fed them — stats are counts, not rows.
timeline
Roadmap lanes over the (already filtered) universe. Lane order: epic lanes alphabetical, then milestone, then cycle, ungrouped last — the epic → milestone → cycle hierarchy the proposal fixes.
