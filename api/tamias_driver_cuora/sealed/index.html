Sealed packs — tamias ADR-0004 / org P-027 / PL-017 task 3.

Tamias carries age-encrypted payloads opaquely: the engine, store, cache, registry, and logs digest ciphertext and never see plaintext. This module is the argv-verb side — the verbs a type: secrets (or any sealed:-carrying) pack’s driver answers:

  • seal — author-side: plaintext files → sealed/ payload layout (sealed/recipients + sealed/<name>.age), plus the sealed: manifest block on stdout — or merged straight into a tamias.yaml with --manifest <path> (surgical text merge: comments and unrelated keys survive; the result is validated as a manifest before it lands).
  • open <pack> <name> / open cuora://<pack>/<name> — decrypt one logical secret to stdout or --out (0600). The escape hatch, like cuora get. <pack> may pin a version — cuora://<pack>@<version>/<name> or <pack@version> <name> — the tamias name@version label spelling, which is how multi-install ambiguity gets resolved.
  • materialize <pack> --out <dir> — decrypt every declared secret into a fresh dir (0600 files).
  • recipients <pack> — list the pack’s age recipients (public keys) and mark which the local keyfile can open.
  • packs — list installed sealed packs in the tamias store.
  • install/deploy/uninstall — lifecycle no-ops: a sealed pack needs no driver action at install time (tamias dispatches them because capabilities.types claims secrets).

All pack/store/identity/age machinery lives in cuora-sealed — the same crate cuora-ops uses for the engine’s cuora://<pack>/<secret> ref fallback, so cuora get/run/ env and these verbs share one resolution + decrypt path.

Secrets safety: plaintext exists only inside decrypt buffers (Zeroizing) between read and write; nothing here logs values — reports carry names, paths, and counts only. Every successful open/materialize emits a cuora audit event (Op::Get) so the materialization trail survives outside the vault path too.

Identity: opening needs an age private key — the same keyfile cuora init manages (~/.config/cuora/identity.txt, mode 0600, $CUORA_IDENTITY_FILE override). --keyfile points at another file in the same format. There is no passphrase prompt: sealed packs are recipient-key only.

Store resolution: <pack> resolves against the tamias install store — $TAMIAS_HOME/store, $XDG_DATA_HOME/tamias/ store, ~/.local/share/tamias/store, ./.tamias/store (--store overrides). --dir <payload> (what tamias driver exec/install dispatch passes) skips the store entirely.
