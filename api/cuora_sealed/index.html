cuora-sealed — the sealed-pack contract, shared by the driver verbs and the engine’s cuora://<pack>/<secret> ref fallback.

Tamias carries age-encrypted payloads opaquely; this crate is the decrypt/seal side both front-ends use:

  • pack resolution against the tamias install store ($TAMIAS_HOME/store → XDG → ~/.local/share/tamias/store → ./.tamias/store, --store/store param overrides);
  • the age identity keyfile (FileIdentity — ~/.config/cuora/identity.txt, $CUORA_IDENTITY_FILE override, --keyfile override);
  • encrypt/decrypt over Zeroizing buffers — plaintext exists only between read and write, never logged;
  • open_pack_ref / pack_declares — the engine’s read path: cuora://<pack>/<secret> resolves to a decrypted value (or a declared-secret probe for cuora check). The pack segment may carry a @<version>/@<sha> pin — cuora://secrets-9aia@1.0.0/registry-token — matching the tamias store label spelling; an unpinned name matching several installs is an ambiguity error, never a silent pick.

The argv verbs (seal/open/materialize/recipients/ packs) live in cuora-driver’s sealed module and call into this crate; cuora-ops calls open_pack_ref when a vault lookup misses on a two-segment ref. Audit emission stays with the callers (each knows its Op and actor).
