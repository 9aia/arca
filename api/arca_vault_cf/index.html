arca-vault-cf — the Cloudflare Worker + D1 vault impl.

A Vault over HTTPS: a self-hosted Worker (source in worker/) fronts a D1 table of opaque rows — (env, ref) → {ciphertext, version, created_at, rotated_at}. The Worker never sees plaintext. Each value is age-encrypted client-side to the configured recipients before it leaves the process; the store holds and returns base64 ciphertext only. This is the same crypto boundary as arca-vault-age (ADR-0001) — a remote store is just a different persistence medium — but with per-secret ciphertext so rows map 1:1 to D1.

§Wire protocol (arca-vault-cf/1)

Bearer auth on every request: Authorization: Bearer <token>, the token read from the env var named by token_env in config — never inline.

VerbPathBody → Response
GET/v1/{env}{"refs": ["a/b", …]} sorted
GET/v1/{env}/{ref}{"ciphertext": "<b64>", "version": n, "created_at": rfc3339, "rotated_at": rfc3339|null}
PUT/v1/{env}/{ref}{"ciphertext": "<b64>", "rotate": bool} → record metadata; rotate:true on a missing ref → 404
DELETE/v1/{env}/{ref}{"removed": bool}

{ref} is the bare ref path (billing/stripe) — both sides split on /. Errors are {"error": "…"} with a non-2xx status. Bookkeeping is server-side: the Worker bumps version, preserves created_at, and stamps rotated_at on rotate, so concurrent writers can’t race client-computed versions.

HTTP uses ureq (blocking, no async runtime) per AGENTS.md.
