Protocol fakes on top of HttpMock — in-memory reference implementations of the two remote surfaces arca talks to:

  • vault_wire — the arca-vault-cf/1 wire protocol, the same semantics arca-vault-cf/worker/index.js implements against D1. Stores base64 ciphertext rows only — never plaintext.
  • cf_secrets_store — the CF API v4 Secrets Store envelope ({success, errors, result}) that arca-deploy-cf pushes to. A real Secrets Store is a plaintext sink, so this fake records what it receives (fake values only, by rule).

cf_secrets_store
A fake CF API v4 Secrets Store. Routes under /accounts/{account}/secrets_store/stores/{store}/secrets: GET ?search= lists (name-substring), POST creates from an array body, PATCH /{id} updates, DELETE /{id} removes — all inside the {success, errors, result} envelope.
vault_wire
The arca-vault-cf/1 wire protocol, in memory. Bearer token required on every request; per-env keyspace; server-side version/created_at/rotated_at bookkeeping (the client’s rotate is a PUT with "rotate": true, 404 on a missing ref).
