Module ops 

Source
Expand description

Engine ops — cli.<verb> wire queries dispatch into the myco engine lib through this binary’s own run verb: each call re-execs tamias-driver-myco run <argv> with the request’s repo as cwd, so myco::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream — and every mutation keeps the engine’s own write-path semantics (per-verb commit, Actor: trailer, worktree lock).

ops answers the ops manifest as JSON — derived from the engine’s own myco::registry::VERBS table, so a verb can’t exist on the CLI and be missing here. Unbounded verbs (serve, ui) are deliberately not ops — they never return, so they live in surfaces instead: surface drivers (tamias-driver-cli / -mcp, the pavo-driver-kit surface layer) expose them as streaming subcommands.

Wire params carry each verb’s declared param schema: arg = positional, opt = --name <v>, flag = --name — the contract pavo-driver-kit’s surface layer renders args from.

cli.<verb> params → myco argv (no argv[0] — run prepends it). Globals go first; the dotted verb name splits into the group path (todo.add → todo add). Declared params map by kind — positionals land last, in schema order.

first_line 🔒

invoke
{"op":"invoke"} — dispatch action (a verb id) through the same argv/exec path cli.<verb> queries use. Unknown actions and spawn failures are Err (wire ok:false); verb outcomes — including nonzero exits — come back Ok with {code, stdout, stderr} in data, mirroring how cli.* queries report the engine’s own exit status as honest data. view is context only (node/item-scoped action resolution is a host concern); repo targeting stays dir/root/cwd like every other op.

manifest
The ops query/ops argv verb payload — self-describing so hosts and agents discover the engine surface without argv help. json/no_commit/dir/root are the engine’s globals — accepted by every op, listed once on the manifest itself.
merge_target 🔒
The invoke target→params merge rule: an object target contributes keys the params lack (explicit params win — the form’s answers override row context); a scalar target fills id when the verb declares one and params don’t (tree-item actions send the row id this way). Anything else is ignored.
missing_required 🔒
Params the verb can’t run without — required flags on argv-ridable params (positionals default required). Wire-only params never reach argv, so they don’t count; dashed aliases satisfy the canonical name.
op_of
Is query an engine op (cli.<verb>)? Returns the verb.
ops 🔒
The ops table — every CLI verb minus hidden and surfaces.
param_json 🔒
Param → the manifest’s typed param — arg/opt/flag as pavo-driver-kit’s surface layer spells them, plus the [ParamSchema] (schema) hosts use for action auto-forms. Wire-only params (Spec patches) can’t ride argv, so they stay out — surfaces only offer what run can pass.
param_schema 🔒
Param → the typed [ParamSchema] carried on the ops manifest’s schema field — hosts auto-generate action forms from it (enum pickers, ref pickers, validation). Driven by the param’s Val type; a few name-driven upgrades for the common text fields (title/note → text, due → date).
present 🔒
A param value counts as present when it’s a non-empty scalar or a non-empty array — {"title":""} is as missing as absent.
pri_options 🔒

scalar 🔒

submit
{"op":"submit"} — thin adapter. This driver declares no form nodes, so a submit only dispatches when form (or the view id itself, when no form is named) resolves to an engine verb — the submitted values become the verb params verbatim. Anything else is ok:false: there is no form to validate against.
values 🔒
All values of a param — arrays flatten, scalars wrap.
workdir 🔒
The child’s working dir — the steering params first (dir/project/root), then $MYCO_DIR, then the driver’s own cwd (pavo inherits the user’s cwd, so a bare cli.status inside repo X reads X’s ledger).
